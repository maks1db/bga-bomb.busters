## Краткое описание правил

Bomb Busters — кооперативная игра для 2–5 игроков. Игроки перерезают одинаковые синие или жёлтые провода действиями «Двойной разрез» и «Одиночный разрез», безопасно вскрывают красные провода только тогда, когда в руке не осталось других проводов, и побеждают, когда все руки пусты. Перерезание красного провода или продвижение детонатора до черепа приводит к общему поражению.

Базовые правила находятся в `doc/RULES.md`. В этот файл нельзя добавлять интерпретации; рабочие допущения должны находиться в `doc/ASSUMPTIONS.md` и сохранять связь с `doc/AUTHOR_QUESTIONS.md`.

## Реализованный прототип

- Миссия 1: 24 синих провода со значениями 1–6, по четыре копии; красных, жёлтых проводов и оборудования нет. Состав подтверждён фотографиями карты.
- Миссия 2: 32 синих провода 1–8 и два случайных жёлтых провода со значениями сортировки 1.1–7.1; красных проводов и оборудования нет.
- Миссия 3: 40 синих проводов 1–10 и один случайный красный 1.5–9.5; жёлтых проводов нет.
- Миссия 4: 48 синих, один красный и два жёлтых провода; для двух игроков используются четыре жёлтых провода.
- Миссия 5: 48 синих, один красный и два жёлтых из трёх кандидатов; для двух игроков используются два красных провода.
- Миссия 6: 48 синих, один красный и четыре жёлтых провода; для двух игроков используются два красных провода.
- Миссия 7: 48 синих и один красный из двух кандидатов; для двух игроков кандидатов три, жёлтых проводов нет.
- Миссия 8: 48 синих, один красный из двух и два жёлтых из трёх кандидатов; для двух игроков красный выбирается из трёх кандидатов и используются четыре жёлтых провода.
- В миссиях 3–8 карты предусматривают оборудование, но оно пока не реализовано согласно H10. Интерфейс прямо сообщает `Equipment cards not implemented yet`.
- `Practice Mission`: 48 синих, два случайных красных и два случайных жёлтых провода. Это отдельный отладочный вариант H8, а не официальная миссия.
- Взрыв на шестом продвижении детонатора пока остаётся временным допущением H9 для всех вариантов.
- Провода хранятся через `ItemManager` в таблице `bombbusters_wire`; `dbmodel.sql` намеренно пустой.
- Раздача учитывает две подставки у каждого игрока при двух участниках и у капитана при трёх. Провода на каждой подставке отсортированы отдельно.
- `getAllDatas` раскрывает значения только владельцу руки. Остальным передаются позиции проводов и публичная информация без скрытых значений.
- Состояния: `SetupInfo` для начальных жетонов, `StartGame` для активации капитана, `PlayerTurn` для действий, `NextPlayer` для пропуска пустых рук и `EndScore` для кооперативного результата.
- Реализованы двойной и одиночный разрез, безопасное вскрытие красных проводов, информационные жетоны, жетоны подтверждения, детонатор, победа, поражение и базовые зомби-ходы.
- Способности оборудования и персонажей пока отсутствуют согласно H10. Начальные жетоны выбираются одновременно согласно H11.

## Механизм миссий

- `modules/php/Missions.php` — единый каталог данных миссий. Для каждой записи задаются номер, английские названия, описания `setupDescription` и `rulesDescription`, список синих значений, количество красных и жёлтых проводов, доступность оборудования и идентификаторы особых правил. Описания уже передаются в `getAllDatas`, но отдельный блок для их показа будет добавлен позже.
- Для специальных проводов `count` — число плиток в раздаче, `candidates` — число известных кандидатов. Например, `count: 2` и `candidates: 3` реализуют настройку «2 из 3»: все три значения получают публичные маркеры с `?`, но в колоду попадают только два случайных. Необязательные `minValue` и `maxValue` ограничивают допустимый диапазон; в миссии 2 для жёлтых установлен `maxValue: 7`, в миссии 3 для красных — `maxValue: 9`.
- `playerCountOverrides` позволяет заменить части конфигурации для конкретного числа игроков. `Missions::get($id, $playerCount)` применяет такой override и удаляет служебную секцию из результата. Для двух игроков миссия 4 увеличивает число жёлтых до четырёх, миссии 5 и 6 — число красных до двух, миссия 7 — число красных кандидатов до трёх, а миссия 8 одновременно меняет красных кандидатов на трёх и жёлтых проводов на четыре.
- `gameoptions.jsonc`, вариант `100`, содержит все реализованные миссии. При добавлении карты обязательно нужно внести её и в `Missions::all()`, и в этот список, иначе она не появится при создании стола. По умолчанию выбрана миссия 1.
- Выбранный идентификатор сохраняется в глобальном `mission_id`; раздача, прогресс, интерфейс и шкала подтверждённых значений используют конфигурацию выбранной миссии с учётом фактического числа игроков.
- `specialRules` пока пуст: это точка расширения для особых правил будущих карт, а не реализованный обработчик.
- Фотографии карт являются исходными материалами и не загружаются на SFTP. `Makefile` отправляет только графические файлы непосредственно из корня `img/`.

## Графика и интерфейс

Игровой графики пока нет. Это не блокирует разработку.

Следует использовать функциональный HTML/CSS-интерфейс с текстовыми заглушками:

- провода — цветные текстовые плитки;
- руки, детонатор и маркеры — обычные DOM-элементы;
- карты оборудования и персонажей — текстовые карточки.

Отображение необходимо отделять от игровой логики, чтобы готовые изображения позже заменили заглушки без переписывания реализации правил.

`gameinfos.jsonc` настроен на Bomb Busters: 2–5 игроков, кооперативный режим, `losers_not_ranked: false` согласно требованиям BGA для кооперативных игр, издатель Cocktail Games (BGG ID 2691), BGG ID игры 413246, ожидаемая длительность 30 минут и автомасштабирование интерфейса. После изменения `gameoptions.jsonc` дополнительно требуется `Reload game options`; выбор миссии действует только для нового стола.

Созданы `Makefile` и `misc/bga_sftp.py`. Используются команды `make check` и `make deploy`; настройки подключения считываются из `.vscode/sftp.json`. Не записывать в этот файл учётные данные или содержимое закрытых ключей.
